# Alfa Only · ИИ-ассистент персонального менеджера

Демонстрационный прототип рабочего места персонального менеджера премиального
сегмента **Alfa Only**. Превращает уже имеющиеся в банке данные о клиенте в
своевременную, персональную и **объяснимую** рекомендацию в момент принятия
решения (концепция решения, отчёт §6.1).

Прототип реализует полный целевой процесс **TO BE** (§3.5): менеджер открывает
приоритизированную очередь кейсов → видит объяснение приоритета и следующее
действие → готовит ответ / сценарий / разбор возражения → подтверждает отправку
→ фиксирует итог и черновик CRM-заметки → решения логируются и попадают в панель
руководителя.

> Это **макет**: данные синтетические (NFR1), «ИИ» работает локально и
> детерминированно, внешних сервисов и ключей не требуется. «Сегодня» в демо —
> фиксированная дата, поэтому время ожидания и сроки кейсов всегда одинаковы и
> воспроизводимы.

---

## Запуск

```bash
npm install
npm run dev      # http://127.0.0.1:4173
```

Прочее: `npm run build` (typecheck + сборка), `npm run preview` (предпросмотр
сборки), `npm run typecheck`.

После запуска открывается экран **Кейсы** с автоматически выбранным верхним
(самым приоритетным) кейсом — можно сразу начинать работу.

## Роль и общая идея

Вы — **персональный менеджер** (в демо это Екатерина Лаврова). У вас портфель
клиентов и поток входящих обращений и задач. Ассистент не общается с клиентом сам
и ничего не отправляет без вашего подтверждения — он:

- **расставляет приоритеты** в очереди и **объясняет**, почему кейс наверху;
- **готовит черновики**: ответ клиенту, сценарий продаж, разбор возражения,
  сводку контакта и заметку в CRM;
- **отвечает на вопросы** по клиенту в рамках доступного контекста и указывает
  источники;
- **запоминает ваши решения** (принял / изменил / отклонил) — они идут в метрики
  руководителя и в будущем калибруют модель.

Вы остаётесь в контуре управления: проверяете, правите и подтверждаете.

## Быстрый старт за одну минуту

Канонический сценарий обработки входящего (UC-01 → UC-03 → UC-04 → UC-06):

1. **Очередь** слева уже отсортирована по приоритету. Верхний кейс — самый важный
   сейчас. Под текстом кейса видна **главная причина приоритета** (например,
   «Клиент ждёт более 4 часов»).
2. В **шапке кейса** посмотрите оценку приоритета (кольцо 0–100) и
   **рекомендуемое действие**. Нажмите **«Почему этот приоритет»** — раскроется
   формула и разбор по 5 факторам.
3. На вкладке **«Диалог»** прочитайте переписку и нажмите **«Черновик
   ассистента»** — появится готовый ответ с обоснованием и источниками.
   Отредактируйте при необходимости.
4. Нажмите **«Отправить»** — сообщение уходит **только после вашего
   подтверждения** (FR11). После отправки ассистент предложит варианты
   следующего шага.
5. Перейдите на **«Итог и CRM»**: нажмите **«Сформировать сводку»**, проверьте
   черновик заметки и **«Сохранить в CRM»**. Здесь же зафиксируйте решение по
   рекомендации (**Принять / Изменить / Отклонить**).
6. Кейс отметится как **«обработано»**. Внизу появится кнопка **«Следующий
   кейс →»** — она ведёт к следующему *необработанному* кейсу. Так очередь
   проходится без возврата к списку.

Проактивный сценарий (UC-02): откройте экран **«Подбор под продукт»**, выберите
продукт — получите ранжированный список клиентов с наибольшей склонностью к
покупке и объяснением.

## Навигация и горячие клавиши

- **Верхнее меню** переключает три экрана: **Кейсы** · **Подбор под продукт** ·
  **Аналитика**. На пункте «Кейсы» — счётчик необработанных кейсов.
- **Справа вверху** — переключатель менеджера (Екатерина Лаврова ↔ Михаил
  Дорохов): меняет портфель, очередь и метрики.
- **Поиск** в очереди ищет по имени клиента, заголовку и тексту кейса.
- **Горячие клавиши** (на экране «Кейсы»; подсказка `J K` в шапке очереди):
  - **J** — следующий кейс, **K** — предыдущий (в том порядке, что виден на
    экране; выбранная карточка автоматически подводится в зону видимости);
  - **Esc** — закрыть панель ассистента.

  Клавиши не срабатывают, пока курсор в поле ввода, — печатать ответ они не мешают.

## Экраны и за что они отвечают

### 1. Кейсы — ядро рабочего дня (UC-01, UC-03–UC-06)

Экран построен по принципу «список + рабочая область» (master-detail): слева
очередь, справа всё по выбранному кейсу.

#### Очередь («Очередь на сегодня»)

Отвечает за приоритизацию потока (UC-01, FR1) и быструю ориентировку.

- **Карточка кейса** показывает: имя клиента и объём активов, **оценку
  приоритета** (число), суть обращения/задачи, а под ней — **главный фактор
  приоритета** (объяснимость прямо в очереди, NFR2). Ниже — канал (чат / звонок /
  встреча), срок и продукт. Метка **«Входящее»** отмечает непрочитанное
  обращение, **«нужны данные»** — неполный профиль.
- **Группировка по уровню**: высокий (≥70) · средний (40–69) · низкий (<40).
- **Фильтры**: Все / Входящие / Задачи. **Сортировка**: По приоритету / По сроку.
- **«обработано»** — кейс, по которому в этой сессии уже отправлен ответ или
  зафиксировано решение; карточка приглушается, давая ощущение прогресса.
- **«сбой сервиса»** (внизу шапки очереди) — имитация недоступности сервиса
  приоритизации (исключение UC-01, NFR6): очередь переключается на сортировку
  **по времени ожидания**, оценки скрываются, интерфейс остаётся рабочим. Кнопка
  «восстановить сервис» возвращает обычный режим.

#### Шапка кейса

Отвечает за объяснимость и следующее действие (NFR2).

- Личность клиента: аватар, сегмент, должность/город/возраст, объём активов,
  уровень ценности, риск оттока, теги.
- **Кольцо приоритета** (0–100) и уровень.
- **«Рекомендуемое действие»** — что сделать дальше и ожидаемый эффект
  (ИИ-блок, перламутровый слой).
- **«Почему этот приоритет»** — раскрывает формулу, **разбор по 5 факторам**
  (балл, вес, вклад, причина) и, если данных не хватает, перечень пробелов
  («кейс остаётся в очереди с пометкой», без домысливания — NFR4).

#### Вкладка «Диалог» (UC-03, UC-04, FR11)

Переписка с клиентом и подготовка ответа.

- Лента сообщений; если входящих ещё нет — подсказка, что это проактивный повод
  связаться.
- **Композер ответа** с пометкой источника текста (Вручную / Из сценария / Из
  разбора возражения / Черновик ассистента).
- **«Черновик ассистента»** генерирует ответ и показывает **обоснование и
  источники**.
- Гарантия **«Уходит только после подтверждения»** — отправки без вашего клика
  нет (принцип участия человека).
- После отправки — **варианты следующего сообщения**.

#### Вкладка «Сценарий» (FR3, FR4, FR5)

Подготовка персональной коммуникации.

- **Персональный сценарий**: задайте цель контакта и (необязательно) уточнение
  («сделай мягче и короче»). Ассистент даёт **опорные тезисы** и **три варианта
  текста** — Структурный / Мягкий / Короткий. Любой можно **«Использовать как
  ответ»** (перенесётся в композер «Диалога»).
- **Отработка возражения**: вставьте реплику клиента — ассистент определит **тип
  возражения**, предложит **варианты ответа с обоснованием**, при необходимости
  пометит **эскалацию**, и отдельно перечислит **«Чего не говорить»**.

#### Вкладка «Итог и CRM» (FR6, FR8, FR9)

Фиксация результата контакта.

- **Решение по рекомендации** (FR8): **Принять / Изменить / Отклонить** +
  комментарий (для «Изменить» комментарий обязателен). Логируется отдельно от
  заметки и формирует данные для обучения моделей.
- **Сводка контакта и черновик CRM** (FR6): по кнопке **«Сформировать сводку»**
  ассистент собирает итог (результат, следующий шаг, ключевые моменты) и
  **черновик заметки**. Заметка **сохраняется только после подтверждения**
  («Сохранить в CRM») — можно также отклонить черновик.
- **История по клиенту** (FR9): сохранённые заметки и зафиксированные контакты.

#### Вкладка «Клиент» (FR7)

Полный профиль для подготовки к контакту.

- **Профиль** из систем банка (должность, город, риск-профиль, активы, свободная
  ликвидность, последний контакт и т. д.); при отсутствии заметки — честная
  пометка о неполноте профиля.
- **Портфель продуктов** клиента.
- **Склонность к покупке** по каждому продукту (кольцо + причина), раскрывается в
  **разбор по 5 факторам**; при высоком риске оттока показывается приоритет
  удержания.

#### «Кейс обработан» и переход к следующему

Когда по кейсу отправлен ответ или зафиксировано решение, внизу появляется панель
**«Кейс обработан · Следующий кейс →»**. Кнопка — **ручная** (не автоматическая):
она переводит к следующему *необработанному* кейсу очереди, не нарушая порядок
работы и оставляя последний шаг за вами. Если необработанных не осталось —
«Очередь разобрана».

#### Ассистент по кейсу (боковая панель, FR9 / NFR4)

Кнопка **«Ассистент»**. Свободные вопросы по клиенту: ассистент отвечает **только
на доступном контексте** и **указывает источники**, а при нехватке данных честно
говорит, что их нет (анти-галлюцинация). Подсказки-вопросы показываются до начала
диалога; история переписки с ассистентом сохраняется по кейсу. Закрыть — крестиком
или клавишей **Esc**.

### 2. Подбор под продукт (UC-02, FR2, FR7)

Проактивный продуктовый сценарий: «кому предложить этот продукт».

- **Выбор продукта** (карточки сверху).
- **Карточка продукта**: суть предложения и сколько клиентов из портфеля имеют
  заметную склонность.
- **Ранжированный список клиентов**: место, оценка склонности (кольцо), **главная
  причина**, метка **«Удержание важнее»** для клиентов с риском оттока. Кнопка
  **«Разбор»** раскрывает **5 факторов** склонности; **«К клиенту»** открывает
  кейс этого клиента на экране «Кейсы».
- Если у продукта мало данных или нет подходящих клиентов — честное уведомление и
  базовый отбор по правилам.

### 3. Аналитика — панель руководителя (UC-07, FR10)

Как менеджеры применяют рекомендации ассистента — основа для оценки эффекта
внедрения.

- **KPI-карточки**: **Использование** (доля рекомендаций, по которым принято
  решение) · **Принятие** (приняты без правок) · **Качество использования**
  (приняты или доработаны) · **Покрытие приоритетных** (доля высокоприоритетных
  кейсов с решением).
- **Решения по рекомендациям**: распределение Принято / Изменено / Отклонено
  (полоса + легенда) и таблица по менеджерам.
- **Последние решения**: лента свежей обратной связи с комментариями менеджеров.
- Метка **«Предварительные данные»** — когда решений ещё мало для устойчивых
  выводов.

## Методика приоритизации (§6.2)

```
Приоритет = 0,25·Ожидание + 0,30·Ценность + 0,20·Срочность
          + 0,15·Потенциал + 0,10·Риск оттока
```

Каждый фактор измеряется в баллах 0–100 по шкалам Таблицы 21 отчёта. Итог 0–100
делит кейсы на уровни: высокий (≥70), средний (40–69), низкий (<40). Для каждого
кейса показываются оценка, разбор по факторам, причины и рекомендуемое действие
(объяснимость, NFR2).

**Склонность к покупке** (§6.3) считается по 5 факторам: соответствие продукта,
платёжеспособность, поведенческий сигнал, глубина отношений, пробел в портфеле.

## Принципы (§6.1)

Участие человека (FR11/NFR3) · объяснимость (NFR2) · ограниченный контекст без
домысливания (NFR4) · проверяемость (история, FR9) · развиваемость · работа
вокруг клиентского кейса.

## Демо-механики и состояния

- **Синтетические данные (NFR1).** Никаких реальных персональных данных. Портфель:
  15 клиентов, 5 продуктов, 28 продуктовых позиций, 20 задач, 20 диалогов,
  110 сообщений, 19 инсайтов, 4 CRM-заметки, 7 событий обратной связи, 2 менеджера.
- **Фиксированные «демо-часы».** Время ожидания и сроки рассчитаны от
  фиксированного «сейчас» — демонстрация воспроизводима.
- **Сохранение работы (FR9).** Отправленные сообщения, заметки, решения и история
  ассистента сохраняются в `localStorage` (ключ `alfa-only-runtime-v1`) и
  переживают перезагрузку. Чтобы вернуть прототип к исходному состоянию, очистите
  для сайта localStorage (DevTools → Application → Local Storage) или выполните в
  консоли `localStorage.clear()` и обновите страницу.
- **Имитация сбоя сервиса (UC-01 / NFR6).** Кнопка «сбой сервиса» в очереди
  показывает запасной режим без оценок.
- **Переключение менеджера.** В правом верхнем углу — два менеджера с разными
  портфелями (видно, как меняются очередь и метрики).

## Архитектура

Прототип повторяет целевую архитектуру (§6.4) в упрощённом, обратимом виде:

```
src/
  domain/        «ИИ-оркестратор»: движки приоритизации, склонности, метрик,
                 сборка очереди и контекста — чистая бизнес-логика
  ai/            «LLM-шлюз + модель»: детерминированные генераторы (сценарии,
                 возражения, сводки, ответы, чат) за единым контрактом AIContext.
                 Замена на реальную LLM не меняет контракт (§6.4.2)
  data/          «тестовая база» (SQLite-эквивалент): клиенты, продукты, задачи,
                 диалоги, сообщения, инсайты, заметки, follow-up, обратная связь —
                 фиксированные демо-часы (clock.ts)
  hooks/         клавиатурная навигация по очереди (useGlobalKeyboard)
  store/         состояние приложения и рантайм-мутации (отправка, заметки,
                 обратная связь, история) с сохранением в localStorage
  components/    переиспользуемые элементы (объяснимость, очередь, вкладки кейса)
  screens/       Кейсы / Подбор под продукт / Аналитика
  styles/        токены бренда (tokens.css) + компоненты (app.css)
```

**Почему без бэкенда.** Прототип проверяет пользовательские сценарии, методику
приоритизации и качество ИИ-функций — то есть содержание решения. Логика вынесена
в чистые модули `domain/` и `ai/` за стабильными контрактами, поэтому переход к
пилоту (реальная LLM, источники банка, SFA/CRM) сводится к замене реализации
абстракций, а не к переписыванию (NFR10).

## Стек

React 19 · TypeScript 5.9 · Vite 7. Шрифты Manrope (заголовки) + Inter (текст).
Визуальный язык — по брендбуку Альфа-Банка: спокойная белая база, графитовый
текст, красный как функциональный акцент, светлый перламутровый слой для
ИИ-блоков.
