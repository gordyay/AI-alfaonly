# Alfa Only · ИИ-ассистент персонального менеджера

Демонстрационный прототип рабочего места персонального менеджера премиального
сегмента **Alfa Only**. Превращает уже имеющиеся в банке данные о клиенте в
своевременную, персональную и **объяснимую** рекомендацию в момент принятия
решения (концепция решения, отчёт §6.1).

Прототип реализует полный целевой процесс **TO BE** (§3.5): менеджер открывает
приоритизированную очередь кейсов → видит объяснение приоритета и следующее
действие → готовит ответ / сценарий / разбор возражения → подтверждает отправку
→ фиксирует итог и черновик CRM-заметки → решения логируются и попадают в панель
руководителя.

Архитектурно это **веб-приложение с бэкендом** (отчёт §6.4.2): сервисный слой на
FastAPI + база SQLite + интерфейс на React. Все данные синтетические (NFR1),
«ИИ» по умолчанию работает детерминированно — демонстрация воспроизводима и не
требует внешних ключей.

## Архитектура

Прототип воспроизводит целевую архитектуру (§6.4) в упрощённом, обратимом виде —
«интеллектуальный слой поверх рабочего места», а не замена CRM.

```
alfa-only-assistant/
  backend/                 Сервисный слой = «ИИ-оркестратор» целевой архитектуры
    app/
      domain/              Приоритизация (6.2), склонность (6.3), метрики,
                           очередь, сборка контекста — чистая бизнес-логика
      ai/                  Абстракция ИИ-провайдера (LLM-шлюз): детерминированный
                           провайдер по умолчанию + опциональный Groq
      routers/             REST API (очередь, кейс, ИИ-функции, обратная связь)
      db.py                Тестовая база SQLite (наполняется из app/seed/seed.json)
      schemas.py           Pydantic-схемы запросов
    tests/                 Pytest: паритет, API, действия, архитектура, данные
  src/                     Интерфейс на React = «ИИ-панель»
    api/                   HTTP-клиент + справочные данные (клиенты/продукты)
    screens/ components/   Экраны и компоненты (тонкий клиент, без бизнес-логики)
    domain/ styles/        Типы и дизайн-токены бренда
  scripts/export-seed.ts   Детерминированный экспорт seed-данных → SQLite
  e2e/                     Playwright — сквозные сценарии интерфейса
```

**Соответствие контуров (отчёт, таблица 26):**

| Компонент целевой архитектуры | Чем замещён в прототипе |
|---|---|
| Системы банка (MDM/СХК/OCRM/DWH/EQ-АБС/VOC) | тестовая база SQLite (`app/seed/seed.json`) |
| ИИ-оркестратор | сервисный слой FastAPI (`backend/app/domain` + `routers`) |
| LLM-шлюз + изолированная LLM | абстракция `AIProvider` (детерминированный / Groq) |
| ИИ-панель в интерфейсе CRM | отдельное веб-приложение на React |
| Журнал аудита, метрики, DWH | таблицы обратной связи/истории в SQLite + панель руководителя |

**Почему так.** Логика вынесена в чистые модули `domain/` и `ai/` за стабильными
контрактами, поэтому переход к пилоту (реальная LLM в изолированном контуре,
источники банка, SFA/CRM) сводится к замене реализации абстракций, а не к
переписыванию (NFR10). Доменная логика и тексты ИИ-функций совпадают с прежним
автономным прототипом до единицы баллов.

## Запуск

Нужны **Python 3.11+** (рекомендуется 3.12) и **Node 18+**.

```bash
make setup     # venv бэкенда + зависимости Python и npm
make dev       # бэкенд :8000 + интерфейс :4173 одновременно
```

Открыть **http://127.0.0.1:4173**. Можно запускать сервисы по отдельности
(в двух терминалах): `make backend` и `make frontend`.

Без `make` — вручную:

```bash
# бэкенд
python3.12 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.txt
cd backend && .venv/bin/uvicorn app.main:app --port 8000 --reload
# интерфейс (в другом терминале)
npm install && npm run dev
```

Адрес API настраивается переменной `VITE_API_URL` (по умолчанию
`http://127.0.0.1:8000/api`). **Сброс демо-данных:** `make clean` (удаляет
`backend/*.db`) — база пересоберётся из seed при следующем запуске.

## Роль и общая идея

Вы — **персональный менеджер** (в демо это Екатерина Лаврова). Ассистент не
общается с клиентом сам и ничего не отправляет без вашего подтверждения. Он:

- **расставляет приоритеты** в очереди и **объясняет**, почему кейс наверху;
- **готовит черновики**: ответ клиенту, сценарий продаж, разбор возражения,
  сводку контакта и заметку в CRM;
- **отвечает на вопросы** по клиенту в рамках доступного контекста и указывает
  источники;
- **запоминает решения** (принял / изменил / отклонил) — они идут в метрики
  руководителя и в будущем калибруют модель.

## Быстрый старт за одну минуту

1. **Очередь** слева отсортирована по приоритету; под текстом кейса — главная
   причина приоритета (например, «Клиент ждёт более 4 часов»).
2. В **шапке кейса** — оценка (кольцо 0–100) и **рекомендуемое действие**.
   Нажмите **«Почему этот приоритет»** — формула и разбор по 5 факторам.
3. Вкладка **«Диалог»** → **«Черновик ассистента»** даёт готовый ответ с
   обоснованием и источниками.
4. **«Отправить»** — сообщение уходит **только после подтверждения** (FR11).
5. **«Итог и CRM»** → **«Сформировать сводку»**, проверьте черновик заметки и
   **«Сохранить в CRM»**; зафиксируйте решение (**Принять / Изменить / Отклонить**).
6. Кейс отметится как **«обработано»**, появится **«Следующий кейс →»**.

## Навигация и горячие клавиши

- **Верхнее меню**: Кейсы · Подбор под продукт · Аналитика (на «Кейсы» — счётчик
  необработанных).
- **Справа вверху** — переключатель менеджера (меняет портфель, очередь и метрики).
- **Горячие клавиши** (экран «Кейсы», подсказка `J K` в шапке очереди): **J/K** —
  следующий/предыдущий кейс, **Esc** — закрыть панель ассистента. В поле ввода не
  срабатывают.

## Экраны и за что они отвечают

### 1. Кейсы — ядро рабочего дня (UC-01, UC-03–UC-06)

«Список + рабочая область» (master-detail): слева очередь, справа всё по кейсу.

- **Очередь** (UC-01, FR1): карточка несёт имя клиента и активы, **оценку
  приоритета**, суть обращения и под ней — **главный фактор** (объяснимость в
  очереди, NFR2), канал, срок, продукт. Метки «Входящее» и «нужны данные».
  Группировка по уровню (высокий ≥70 / средний 40–69 / низкий <40). Фильтры
  (Все / Входящие / Задачи), сортировка (по приоритету / по сроку), поиск.
  **«обработано»** приглушает закрытые кейсы. **«сбой сервиса»** — запасной режим
  (UC-01/NFR6): сортировка по времени ожидания, оценки скрыты.
- **Шапка кейса**: личность клиента, кольцо приоритета, **рекомендуемое
  действие**, раскрываемое **«Почему этот приоритет»** (формула + 5 факторов +
  пробелы в данных, NFR4).
- **Диалог** (UC-03/04, FR11): переписка, **черновик ассистента** с обоснованием
  и источниками, гарантия «уходит только после подтверждения», варианты
  следующего шага после отправки.
- **Сценарий** (FR3/4/5): персональный сценарий (цель + уточнение → тезисы и
  три варианта: Структурный / Мягкий / Короткий) и разбор возражения (тип,
  варианты ответа с обоснованием, эскалация, «чего не говорить»).
- **Итог и CRM** (FR6/8/9): решение по рекомендации (Принять/Изменить/Отклонить),
  сводка контакта + черновик заметки (сохраняется только после подтверждения),
  история по клиенту.
- **Клиент** (FR7): профиль из систем банка, портфель продуктов, склонность к
  покупке по каждому продукту (5 факторов, раскрывается).
- **Ассистент по кейсу** (боковая панель, FR9/NFR4): вопросы по клиенту — ответы
  только на доступном контексте, с источниками; история сохраняется на бэкенде.

### 2. Подбор под продукт (UC-02, FR2/FR7)

Выбор продукта → ранжированный список клиентов по склонности к покупке: место,
оценка (кольцо), главная причина, метка «Удержание важнее», разбор по 5 факторам,
кнопка «К клиенту».

### 3. Аналитика — панель руководителя (UC-07, FR10)

KPI: использование, принятие, качество, покрытие приоритетных. Распределение
решений (принято/изменено/отклонено) + таблица по менеджерам и лента последних
решений.

## API (основные эндпоинты)

```
GET  /api/health                          состояние + активный ИИ-провайдер
GET  /api/managers · /clients · /products справочные данные
GET  /api/queue?managerId=                очередь кейсов (с флагом handled)
GET  /api/cases/{id}                       полный контекст кейса
POST /api/cases/{id}/reply-draft           черновик ответа (UC-04)
POST /api/cases/{id}/script                сценарий продаж (FR3/FR5)
POST /api/cases/{id}/objection             разбор возражения (FR4)
POST /api/cases/{id}/summary               сводка + черновик CRM (FR6)
POST /api/cases/{id}/chat                  ассистент по кейсу (FR9/NFR4)
POST /api/cases/{id}/send                  отправить ответ (FR11)
POST /api/feedback · /notes                решение (FR8) · заметка CRM (FR6)
GET  /api/products/{id}/ranking?managerId= склонность клиентов (UC-02)
GET  /api/supervisor                       метрики руководителя (UC-07)
```

Интерактивная схема — `http://127.0.0.1:8000/docs` (OpenAPI).

## Методика приоритизации (§6.2) и склонность (§6.3)

```
Приоритет = 0,25·Ожидание + 0,30·Ценность + 0,20·Срочность
          + 0,15·Потенциал + 0,10·Риск оттока          (баллы 0–100, табл. 21)
```

Итог 0–100 делит кейсы на уровни (≥70 / 40–69 / <40). Для каждого кейса видны
оценка, разбор по факторам, причины и действие (объяснимость, NFR2).

**Склонность** считается по 5 факторам: соответствие продукта, поведенческий
сигнал, платёжеспособность, глубина отношений, пробел в портфеле.

## Тесты

```bash
make test-backend   # Pytest: 58 тестов (паритет баллов, API, действия, данные)
make e2e            # Playwright: 7 сквозных сценариев (UC-01…UC-07)

```

Перед E2E нужны браузеры Playwright: `npx playwright install chromium`. Внешние
вызовы LLM в тестах заменяются детерминированным провайдером (§6.5).

## Принципы (§6.1) и демо-механики

Участие человека (FR11/NFR3) · объяснимость (NFR2) · ограниченный контекст без
домысливания (NFR4) · проверяемость (история, FR9) · развиваемость · работа
вокруг клиентского кейса.

- **Синтетические данные (NFR1):** 15 клиентов, 5 продуктов, 28 продуктовых
  позиций, 20 задач, 20 диалогов, 110 сообщений, 19 инсайтов, 4 CRM-заметки,
  7 событий обратной связи, 2 менеджера. Реальные персональные данные не
  используются.
- **Фиксированные демо-часы** — время ожидания и сроки воспроизводимы.
- **Хранение результатов (FR9):** отправленные сообщения, заметки, решения и
  история ассистента сохраняются в SQLite и переживают перезагрузку.
- **Имитация сбоя сервиса (UC-01/NFR6)** и **переключение менеджера** — на экране
  «Кейсы».
